# 融合与旧数据

## 一个入口，按结果分工

聊天消息与附件只由 `components/chat` 解析；回放与课程复用该组件中的 ASR / Word 引擎。公众号只由 `components/articles` 管理账号、文章、缓存、订阅、去重与 Word 回执。`services/` 负责运行时与任务路由，不复制另一份解析算法。媒体依赖保留原有实现。

原微信数据提取与公众号独立目录已退役；当前安装入口是本套件 main。历史 Git 分支用于追溯，不是安装更新通道。

## 吸收的能力

- 聊天：精确会话/时间/类型、账号绑定、附件关联、语音 MP4、原子导出及 Windows 原生源码预览。
- 公众号：保留缓存、正文与覆盖证据、增量去重、交付回执、缺口保留、可见历史与本地控制台；保留访问受限的共享停止条件和会话实证校验。
- 文章只读检查不会初始化空库。数据库写连接在事务边界及时关闭，避免遗留连接在后续检查期间因垃圾回收而冲刷 WAL。
- 回放与课程保留原有目录、音轨、转写和 Word 分层验收；课程讲义能力保留。

## 旧环境继续保留

本次更新只改源码，不读取或搬迁任何用户账号与旧数据库。套件沿用自己的私有目录与配置。已有独立安装仍保留原目录；如需合入数据，先停止同库的重复 worker，明确账号、文件清单、去重方式和恢复备份，再制定独立迁移方案。不要把旧调度的启用状态直接带入新套件。
